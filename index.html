06 · Falha em destaque: BOLA / IDOR

Um ID diferente não deveria liberar outro usuário.

❌ API vulnerável

GET /api/faturas/101
GET /api/faturas/102

Trocar o ID pode expor a fatura de outra pessoa.

✅ API protegida

buscarFatura({
id: 102,
dono: usuario.id
})

O servidor valida a permissão sobre o objeto.

07 · Demonstração interativa simulada

Uma requisição, duas respostas possíveis.

Ana está logada

GET /api/faturas/102
Authorization: Bearer <token-da-ana>

A fatura 102 pertence a Bruno.

Escolha uma opção para ver o resultado.

O ponto principal

  • Autenticação identifica Ana.
  • Autorização deve ser verificada sobre a fatura 102.
  • O servidor não pode confiar apenas no identificador enviado.

09 · Estratégias de proteção

Como construir APIs mais seguras?

  • HTTPS/TLS: dados protegidos em trânsito.
  • Tokens e sessões: assinatura, validade e contexto verificados.
  • Autorização: recurso e função checados em cada pedido.
  • Validação: entrada e saída com campos permitidos.
  • Limites: taxa, paginação e tamanho de requisições.
  • Monitoramento: logs, testes e inventário de endpoints.

10 · Caso notável

Peloton (2021): falha no controle de acesso da API.

O problema

Uma vulnerabilidade divulgada permitia consultar informações de perfis por API quando o acesso deveria ser restrito.

A lição

As permissões precisam ser aplicadas nas respostas do servidor, e não apenas na interface visual.

Cobertura: TechCrunch, maio de 2021.

11 · Aplicação na rotina de desenvolvimento

Checklist antes de publicar.

  • Mapear endpoints e permissões.
  • Negar acesso por padrão no back-end.
  • Testar com contas e perfis diferentes.
  • Proteger segredos e usar HTTPS.
  • Limitar requisições e tamanho dos dados.
  • Revisar logs, dependências e versões antigas.

12 · Conclusão
Uma API segura não apenas reconhece o usuário.
Ela verifica o que ele pode acessar — em cada requisição.

Identidade + permissão + validação + monitoramento.
